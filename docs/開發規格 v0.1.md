# 雙半馬冒險路線 Cloudflare 版：開發規格 v0.1

日期：2026-11-07　用途：交給 Claude Code 在本機開發。本文是唯一的需求依據，請先讀完再動手。

## 一、目標與已決定事項

把目前跑在 claude.ai 的「雙半馬冒險路線」頁面（頁面版本 18）搬到 Cloudflare，讓它：

1. 不依賴 claude.ai 的資料庫，資料存在自己的 Cloudflare 帳號。
2. 能由排程自動從 intervals.icu 同步，金鑰放在 Cloudflare 的機密設定，不進程式碼、資料庫或文件。
3. 同時有兩種存取方式（Dino 已確認「兩種都做」）：
   - **完整版**：只有指定 email 能進，用 Cloudflare Access 保護。Dino 可編輯；太太等人只能看。
   - **公開展示版**：任何人有網址都能看，只顯示淨化過的資料，不含任何身體數字。
4. 範圍是**完整移植，分階段**（Dino 已確認）。

不做的事：不寫回 intervals.icu（同步是單向、只用 GET）；不做多使用者帳號系統；不在這一版做對外服務或收費。

## 二、現況（要搬的東西）

- 頁面原始碼：`source/adventure_page_v18_source.html`。單一檔案，內嵌 CSS 與 JavaScript，無外部程式庫，只用 Google Fonts（DotGothic16、Press Start 2P）。約 880 行、81 KB 左右，可以整份讀完。
- 角色像素資料已內嵌在頁面的 `ACT` 物件；獨立備份在 `source/sprite_data.json`。**不要重畫角色，不要憑文字描述重做**。
- 展示版範本：`source/showcase_template.html` 與產生程式 `source/showcase_gen.py`、資料範例 `source/showcase_snapshot_example.json`。
- 現有資料（種子）：`seed/seed_2026-11-07.json`，包含 workouts 7 筆、wellness 10 筆、config/ranges。
- 資料庫是 Firestore 風格的 API，頁面裡用到：`db.collection(name).onSnapshot(cb)`、`.add(obj)`、`.doc(id).set(obj)`、`.doc(id).delete()`、`db.doc('config/ranges')`、`db.doc('config/races')`。另有 `window.claude.use('user')`（只用 `can('data.write')`）與 `window.claude.use('downloads')`（只用 `save({filename,data})`）。

## 三、架構

建議兩個 Worker，各自綁定同一個 D1，避免用路徑規則混合「受保護」與「公開」。

| 項目 | 完整版 Worker `adventure` | 展示版 Worker `adventure-demo` |
|---|---|---|
| 網址 | 自訂網域或 workers.dev 的子網址 | 另一個網址 |
| 保護 | Cloudflare Access（Allow 指定 email） | 無，公開 |
| 內容 | 完整頁面、`/api/*`、排程同步 | 靜態展示頁與一支只讀端點 `/api/snapshot` |
| 資料 | 讀寫 D1 | 只讀 D1，且只回傳淨化後的欄位 |
| 排程 | 有（Cron Trigger） | 無 |

靜態頁面用 Workers 的靜態資源功能提供；後端程式碼同一個 Worker 內處理 `/api/*`。（Pages 與 Workers 的取捨請在開工前查官方文件，不要沿用本文的假設。）

### 資料流

```
intervals.icu --GET--> [排程 Worker] --寫入--> D1 <--讀寫--> [完整版頁面]
                                              \--只讀、淨化--> [展示版頁面]
```

## 四、資料庫（D1）

延續現有集合，欄位名稱沿用，方便種子匯入。草稿 schema 在 `schema.sql`。

| 表 | 主鍵 | 重要欄位 |
|---|---|---|
| `workouts` | `id`（`icu-{事件編號}` 或 `icu-act-{活動編號}`） | `date`、`title`（intervals.icu 原名，不改寫）、`kind`（跑／騎／游／肌力／休息／其他）、`mins`、`desc`、`done`、`done_at`、`key`、`source`、`unplanned`、`note`、`removed_from_icu`、`actual`（JSON：實際時長、距離、均心率、負荷）、`created_at` |
| `wellness` | `date` | `rhr`、`hrv`、`ctl`、`atl`、`sleep_h`、`sleep_score`、`missing`、`source` |
| `config` | `key` | `value`（JSON）。鍵：`ranges`（`rhrMax`、`hrvMin`）、`races`（賽前檢查備註） |
| `checks` | (`race`,`item`) | `done`、`done_at` |
| `checkitems` | `id` | `race`、`label`、`required` |
| `events` | `id` | `t`、`type`、`label`、`extra`（JSON） |
| `sync_log` | `id` | 每次同步一筆：時間、觸發來源、讀取範圍、新增／更新／移除／略過筆數、錯誤 |
| `sync_requests` | `id` | 頁面按鈕留下的請求：時間、狀態 |

寫入規則：頁面勾選的 `done`、`done_at`、`key` 在同步時**不可被覆蓋**；`title`、`date`、`kind`、`mins`、`desc` 以 intervals.icu 為準。完整對應規則見專案文件《資料同步功能設計 v0.1》第四節，請照該節實作。

## 五、API（完整版 Worker）

最小設計，讓頁面程式碼幾乎不用改：

| 方法與路徑 | 作用 |
|---|---|
| `GET /api/{table}` | 讀整張表，回傳 `[{id, ...欄位}]` |
| `PUT /api/{table}/{id}` | 取代一筆（對應 `set`） |
| `PATCH /api/{table}/{id}` | 合併欄位（對應 `update`） |
| `POST /api/{table}` | 新增並回傳 id（對應 `add`） |
| `DELETE /api/{table}/{id}` | 刪除 |
| `GET /api/config/{key}`、`PUT /api/config/{key}` | 設定文件 |
| `POST /api/sync-requests` | 留下同步請求 |

只允許 `workouts`、`wellness`、`config`、`checks`、`checkitems`、`events`、`sync_requests`；其他一律 404。所有寫入端點需要驗證為「可編輯者」。

### 頁面端：資料庫轉接層

**不要改寫頁面邏輯。** 新增 `db-shim.js`，提供與目前頁面相同形狀的物件：

- `shim.collection(name).onSnapshot(cb, errCb)`：先 `GET` 一次，之後每次本頁寫入成功就重新 `GET` 並呼叫 `cb`，另每 30 秒輪詢一次。`cb` 收到的 snapshot 要有 `docs[].id`、`docs[].data()`、`metadata.fromCache=false`。
- `shim.doc('config/ranges')`：`onSnapshot`、`set`；snapshot 有 `exists`、`data()`。
- `.add`、`.doc(id).set/update/delete` 對應上表。
- `claude.use('user')` 的替代：從 `/api/me` 取得 `{canWrite}`，供 `can('data.write')` 使用。
- `claude.use('downloads')` 的替代：用 Blob 與 `<a download>` 觸發下載；失敗時保留頁面上「長按圖片儲存」的說明（手機瀏覽器不一定允許下載）。

頁面開頭原本的 `window.claude.use('db')` 判斷改成使用 shim；**其他所有函式維持原樣**。

## 六、驗證與權限

- 完整版用 Cloudflare Access 保護；政策只 Allow 指定 email（Dino、太太）。外部 email 的登入方式請查官方的「一次性 PIN」文件，**本文沒有驗證過細節**。
- Worker 必須自己驗證 `Cf-Access-Jwt-Assertion`（不要只信任網路層）。驗證方式請查官方「Validate JWTs」說明。
- 角色：Dino 的 email 為可編輯者；其他被允許的 email 為只讀（寫入端點回 403）。email 清單放在 Worker 的變數，不寫死在程式碼裡。
- 只讀者看到的頁面：隱藏「新增課表」、勾選與調整範圍的控制項，並顯示「目前只能檢視」（頁面已有 `canWrite=false` 的處理，沿用）。
- 展示版 Worker 不需驗證，但**只能**透過 `/api/snapshot` 取資料，端點在程式裡就只組出淨化欄位，不是靠前端隱藏。

## 七、同步 Worker（排程）

- 時間：台北 07:00 與 22:00，即 UTC 23:00（前一日）與 14:00。Cron 的時區與星期編號規則請查官方文件。
- 認證：intervals.icu 用 HTTP Basic，帳號固定 `API_KEY`，密碼是金鑰；選手代號 `i572505`，Base URL `https://intervals.icu/api/v1`。
- **金鑰只放機密設定**（用 `wrangler secret put`），本機開發用 `.dev.vars`，且 `.gitignore` 要排除。金鑰不得出現在程式碼、日誌、資料庫、文件、回應中。
- **只能使用 GET**。程式裡不得有對 intervals.icu 的 POST、PUT、DELETE。
- 資料對應、衝突處理、缺資料判定、例外處理，完全依《資料同步功能設計 v0.1》第四節與第九節。重點：
  - 課表名稱用原名；活動名稱包含課表名稱才配對成功，否則建立計畫外；時間不到 2 分鐘或距離為 0 的活動略過。
  - wellness 以起床當天為日期；睡眠時數為 0 或 HRV 為空時標記 `missing`；每次同步重讀最近 3 天。
  - 讀到的課表數為 0 時視為可疑，不執行刪除。
  - 同步要可重複執行：連續兩次，第二次應為 0 新增、0 更新。
- 每次同步寫一筆 `sync_log`，並把待處理的 `sync_requests` 標為已處理。
- 頁面上「同步」按鈕只留下請求，並明確寫出「已送出，下次排程處理」，因為它不會立刻同步。

**重要：Dino 之前把 API Key 貼在對話裡，上線前請他在 intervals.icu 重新產生金鑰。** 這個帳號只有一組金鑰，重新產生後舊的立刻失效，其他使用金鑰的流程要一併更新。

## 八、展示版（公開）

- 沿用 `source/showcase_template.html` 的外觀（標題 TODAY'S QUEST，角色做今天的動作）。
- 資料來自 `/api/snapshot`，**只能包含**這些欄位：日期、第幾週、賽事名稱與日期、今天課表的類型／原名／計畫時長／是否完成／實際距離與時間、本週完成數與總數、身體訊號的**顏色狀態**（ok／near／out／missing）。
- **絕對不可包含**：心率、HRV、睡眠、CTL／ATL、課表說明（`desc`）、活動備註裡的心率與負荷、金鑰、email。
- 展示頁不含任何寫入功能。

### 階段 5：切換上線與營運
前四個階段完成並通過驗收後才做。

1. **切換**：
   - 上線前再匯出一次 claude.ai 版的最新資料，重新匯入 D1（先清空再匯入，或用 id 覆蓋）。
   - 確認完整版、只讀 email、展示版都正常後，Dino 才改用新網址；舊的 claude.ai 版先保留唯讀，不刪除。
   - 切換日起，只在新版寫入資料，舊版不再更新，避免兩邊資料不一致。
   - **回退**：新版出問題時，Dino 回到 claude.ai 版繼續用；舊版資料停在切換日，所以切換後的新資料要另外從 D1 匯出補回。
   - 網址：workers.dev 或自訂網域（見「尚待決定」），Access 的政策與網址要對應。
2. **同步失敗通知**：排程同步失敗（金鑰失效、連續 401、讀不到資料）時要讓 Dino 知道。方式在開工時討論（例如頁面頂端的提醒色加上 `sync_log` 的失敗訊息；是否另外通知，由 Dino 決定）。至少要做到：頁面上看得出「最近一次同步失敗」與原因，以及超過 24 小時沒同步時改成提醒色。
3. **金鑰輪替流程**：寫成 `README` 的一節。內容：在 intervals.icu 重新產生金鑰、用 `wrangler secret put` 更新、手動觸發一次同步確認成功、更新 Dino 其他使用金鑰的流程。要提醒：這個帳號只有一組金鑰，重新產生後舊的立刻失效。
4. **備份與還原演練**：定期用 `wrangler d1 export`（指令開工時查證）匯出；至少實際做過一次「匯出、清空、還原」，並核對筆數與抽查內容一致。備份檔含身體資料，存放位置不得公開。
5. **安全複查**：以未登入、只讀 email、可編輯 email、不在名單的 email 四種身分測完整版（未登入與不在名單者不得看到任何資料；只讀者寫入必須被拒）；對展示版端點逐欄位確認沒有第八節禁止的內容。

驗收：上面五項各有一次實際測試的紀錄，並寫進《觀察紀錄》。

## 十一、開發守則（來自 Dino 的使用習慣，請遵守）

1. 外部系統來的名稱與說明**原樣顯示**，不翻譯、不改寫。
2. 任何會失敗或沒作用的操作都要有看得見的回饋（提示訊息或說明文字），不能靜默無反應。
3. 儀表類區塊預設只顯示「今天的狀態」，歷史與趨勢要 Dino 開口才加。
4. 用顏色區隔時，改在最小單位（數字、標籤），不要整塊上色，也不要自行新增 Dino 沒指定的狀態。
5. 新增動畫或 CSS 類別前，確認沒有和既有類別重名（曾因 `.sw` 造成圖例掉落）。
6. 視覺相關的改動要附「所有狀態並排」的測試截圖；測試要截整頁，不只截改的那一塊。
7. 視覺素材一律保存可重現的原始資料與截圖，不只存文字描述。
8. 定稿一個版本就更新原始碼、版本號與文件，並同步到本機資料夾。
9. 提到第三方服務的限制之前先查官方文件；不確定就寫「待查證」。
10. 全程使用繁體中文。
