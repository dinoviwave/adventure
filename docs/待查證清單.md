## 對現有設計的影響（重點）

1. **免費方案 CPU 10 ms 是最大風險。** 同步（整理資料）與 JWT 驗證可能超過；若出現 Error 1102 或同步偶爾失敗，解法是升級付費方案（CPU 30 秒），或把同步邏輯瘦身。需要在 Cloudflare 後台 Metrics 查有無「Exceeded CPU Time Limits」。
2. **D1 免費版每次執行最多 50 次查詢。** 第一次大量同步時，寫入批次與讀取加起來可能超過；平常的同步遠低於。
3. **Access 要「兩層」都調到最長**，才能一個月不用重登；加上 Google 登入與 Instant authentication 就能直接跳轉。
4. **Supabase 免費方案的 session 預設永不過期**，對「很久不用重登」有利；要主動設定時限才需要 Pro。
5. **trilog 日後有兩條可行路徑**：(a) 讓 trilog 的資料庫接受外部身分來源的 token（第三方驗證，自訂 OIDC）；(b) 讓身分專案的 Supabase 當 OIDC 提供者。細節比原先評估的「完全不能搬」寬鬆，但仍要重寫 RLS 的使用者判斷。
6. 可用 D1 Time Travel 當作備份輔助：免費 7 天內可回溯（不取代匯出備份）。
